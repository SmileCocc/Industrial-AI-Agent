# 演示指南

演示约 15 分钟，展示 Agent 如何通过 ERP、MES 的只读 HTTP 接口取数、计算并给出有据可查的结论。下文数字来自 2026-11-20 重置后的数据；模拟数据以重置当天为基准生成，换一天重置后编号日期会变化，但场景结构不变。

## 1. 准备

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\reset-data.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

1. 确认四个服务均输出 `[OK]`，打开 http://127.0.0.1:5173 。
2. 进入「系统配置」，点击「测试模型连接」。显示「已返回原生工具调用」才开始演示。显示「模型服务限流」说明网关当日额度已用完，需要换时间或换额度。
3. 演示结束后运行 `scripts\stop.ps1`。

## 3. 助手提问与核对要点

每次提问约 15–95 秒，取决于模型生成报告的长度。

| 问题 | 模型应调用的工具 | 回答应包含 |
|---|---|---|
| 请做今日工单缺料分析。哪些工单缺哪些物料、差多少、会影响哪些生产计划？ | analyze_material_shortage | WO-20261120-006 缺 IGBT 250 个（90 个可用已分配给在产工单 WO-20261119-001）、散热器 150 个；WO-20261120-007 缺工控 CPU 36 个；WO-20261120-008 缺 MOSFET 300 个（与在产工单竞争） |
| 今日生产计划完成率是多少？哪些产线未达目标？ | analyze_operations（plan） | 总完成率 70.16%；L02 23.35% 最低，L01、L03 等未达标 |
| 哪些物料低于安全库存，对应供应商是谁？ | analyze_operations（inventory） | 7 种物料，如 MAT-1001 缺口 180 个，供应商深圳华芯功率半导体 |
| 最近一周哪些设备出现异常，对生产有什么影响？ | analyze_operations（equipment） | 11-14 至 11-20 共 31 条报警，并关联到受影响工单 |
| 分析今天生产效率下降的可能原因，区分事实和待核实原因。 | analyze_operations（efficiency） | 报警、缺料、延期等事实有数据支撑；无法证明的原因标为「待核实」 |

可以追问「WO-20261120-006 的 IGBT 被哪张工单占用了？」展示多轮对话。也可以打开左侧历史会话，回放之前的报告和轨迹。

## 4. 安全与异常演示（可选）

| 操作 | 预期表现 |
|---|---|
| 停止 ERP（`stop.ps1` 后只启动 `dev.ps1 -Services mes,ai,web`） | 集成页 ERP 显示「异常」；驾驶舱接口返回 502，不显示旧数据；缺料工具返回「ERP 服务请求失败」，轨迹保留失败的请求 |
| 清空 `MODEL_API_KEY` 后重启 AI 服务 | 测试连接和对话返回 503「请配置 OpenAI 兼容模型的地址、名称和密钥」，不会生成伪造回答 |
| 访问未登记接口，如 `/api/erp/admin/sql` | 404「业务接口不存在」 |

## 5. 讲解要点

- Agent 只执行模型返回的原生 tool_calls，没有关键词匹配，也没有预置答案。
- Agent 不连接 ERP/MES 数据库，只调用白名单内的 GET 接口。第一版全部只读，没有任何写操作或设备控制。
- 缺料计算由代码完成：在产工单先占用库存，其余工单按优先级、计划开工时间和工单号排序分配。模型只负责组织语言。
- 模型密钥只在 `backend/.env` 中，日志、对话记录、接口响应和前端构建产物都不包含密钥。
